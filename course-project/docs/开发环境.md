# WSL 开发环境使用说明

课程仓库目录：C:\Users\KYBJB-0201\Desktop\oop\ucas-oop-liuchanghe23。

在 Windows 终端运行 wsl -d Ubuntu，然后执行：

    cd /mnt/c/Users/KYBJB-0201/Desktop/oop/ucas-oop-liuchanghe23
    bash course-project/scripts/dev.sh doctor
    bash course-project/scripts/dev.sh infra
    bash course-project/scripts/dev.sh build
    bash course-project/scripts/dev.sh test-unit
    bash course-project/scripts/dev.sh start svc-task-resource
    bash course-project/scripts/dev.sh start svc-result-processor

测试接口：

    curl --fail http://localhost:8101/hello
    curl --fail http://localhost:8104/hello

停止应用：

    bash course-project/scripts/dev.sh stop

本机使用 Ubuntu 原生 Java 21、Maven、MySQL 8.4 和 Redis 8。数据库 spaceexploration 已根据平台 SQL 初始化。开发账号和连接参数见本地 course-project/.env，该文件被 Git 忽略。应用由当前用户的 systemd 服务管理；关闭单次命令窗口后也能运行，日志位于 course-project/.local/logs/。

从零配置另一套 Ubuntu：

    sudo bash course-project/scripts/setup-wsl.sh

只重新安装和检查本地数据库：

    sudo bash course-project/scripts/setup-native-infra.sh

脚本发现数据库已有表时不会重复导入或覆盖。原生数据库由系统服务管理；如果需要停止：

    sudo systemctl stop mysql redis-server

Docker Engine / Compose 同样已安装，Compose 文件是可选部署方案，默认使用 MySQL 8.4 / Redis 7 镜像。需要 Docker 模式时在 .env 中改 INFRA_MODE=docker；先停止原生数据库以避免端口冲突。当前网络下 Docker Hub 镜像拉取超时，所以本机实际使用原生数据库。

平台基线为上游 main / e000f5c，不包含 dev/iscas。只进行了开发环境相关修正：凭据环境变量化、本地配置、避免重复打包、启用 JUnit 5、网络超时和启动脚本。业务模块仍按 main。

完整故障注入还需要 Kubernetes、ChaosBlade Operator、Jaeger 和被测系统，不属于本次本地基础环境启动验证。故障调度服务启动时就会检查集群。全量测试包含依赖集群的用例，不等同于 test-unit。
