# 4.2 范围与代码基线

## 课程要求

开发独立服务，结合缺陷模板与目标系统的拓扑、配置和代码信息：

1. 建立系统画像，匹配模板中的因果角色与成立条件。
2. 定位风险对象，生成故障调度服务能执行的 ChaosBlade 配置。
3. 根据实验数据判断机制是否激活、预期后果是否出现、证据是否充分。
4. 明确表示不适用、无法判定、执行器不支持等情况。
5. 使用一个目标系统、不少于五条缺陷模板验证，对照人工判断；至少一组修改前后实验。

## 当前基线

平台使用上游 main，提交 e000f5c0e07d929be06f81b4616841690ad513d3。保留原文件版权声明；导入时移除了硬编码 API 密钥、集群令牌和外部数据库密码，并改为本地地址和环境变量。未复制上游 Git 历史或预构建 Helm 压缩包。

已有：任务与配置管理、Jaeger 调用关系查询、故障调度、请求录制回放、单/双故障用例生成、指标统计与文字总结。

待开发：事故缺陷模板、技术适配、条件匹配、机制激活判断、证据结论和修复对照验证。dev/iscas 的风险分析模块不在本次基线内。

目标系统为 OpenTelemetry Demo，独立保存于上游仓库，本课程仓库不重复导入整套多语言源码。已有本地检出位于课程仓库的同级目录。

## 仍需确认

模板格式与来源、画像能否部分人工导入、五条模板的验收口径、执行器能力边界、修复对照是否允许构造缺陷。

已有期中报告属于初步分析，关于缺陷开关数量等内容需要结合实际版本核实；关闭故障开关也不自动等于修复底层缺陷。
